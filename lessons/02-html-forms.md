# 02 — Create an accessible incident report form

[Previous lesson](01-html-foundations.md) · [Course home](../README.md) · [Next lesson](03-css-basics.md)

## Before you start

Complete lesson 01.

## What you will learn

Understand labels, inputs, text areas, select controls, required fields, and native form validation.

## Instructions

1. Read the field rules in the project brief. Plan controls for title, category, severity, and description.
2. Give every control a persistent visible label. Add a short explanation where a field needs it; placeholders are not labels.
3. Add a submit button and a clear demo-data notice. This stage only demonstrates a form; it does not save reports.
4. Set appropriate required fields and length limits. Compare empty, whitespace-only, and valid input; browser checks will not handle every business rule.
5. Navigate the entire form using the keyboard. Plan where field errors and a submission confirmation should appear.

## Done when

- [ ] Clicking a label focuses its control.
- [ ] Keyboard users can reach every control and see where focus is.
- [ ] You can explain why browser validation alone cannot protect a server.

## ChatGPT prompt — guided practice
