# 03 — Style the dashboard with plain CSS

[Previous lesson](02-html-forms.md) · [Course home](../README.md) · [Next lesson](04-responsive-layout.md)

## Before you start

Complete lessons 01–02.

## What you will learn

Learn selectors, the cascade, inheritance, specificity, the box model, spacing, typography, and colors.

## Instructions

1. Create a stylesheet in your implementation repository and connect it to the pages. Start with readable text and consistent spacing.
2. Inspect margin, border, padding, and content for one incident card in developer tools. Change one property at a time and predict the effect.
3. Choose a small palette and use CSS custom properties for repeated colors and spacing. Keep the design understandable without a UI framework.
4. Style buttons, inputs, cards, and status labels consistently. Keep visible keyboard focus and include text with every severity color.
5. Intentionally create a conflicting style, inspect which rule wins, and explain why. Resolve it without repeatedly increasing specificity.

## Done when

- [ ] You can explain margin versus padding on your own card.
- [ ] Severity is understandable without color.
- [ ] Text, controls, and focus indicators remain readable against their backgrounds.

## ChatGPT prompt — guided practice

> Teach me CSS using my incident card. Ask what I expect a spacing change to do, then have me inspect it. Explain the cascade and box model in plain language. Do not provide a stylesheet or CSS snippets.

## ChatGPT prompt — review my attempt

> Review my CSS for repeated values, specificity problems, readability, and focus styles. Suggest the smallest improvement and ask me to implement it. I will share only fictional data and remove credentials before sharing my work.
