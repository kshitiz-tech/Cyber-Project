# 17 — Publish the frontend learning demo

[Previous lesson](16-testing-and-accessibility.md) · [Course home](../README.md) · [Next lesson](18-backend-with-node.md)

## Before you start

Complete lesson 16 and the core checklist in the project brief.

## What you will learn

Learn production builds, static hosting, deployment paths, direct-route handling, and honest portfolio documentation.

## Instructions

1. Choose a static host using Vite’s deployment guide. GitHub Pages is one option for the frontend; it does not run an Express backend.
2. Follow the current host-specific build and deployment instructions in your implementation repository. Set the correct base path when hosting under a repository subpath.
3. For a simple GitHub Pages demo, choose hash-based routing or follow a documented fallback strategy. For another host, configure the documented SPA rewrite. Test the actual deployed URL.
4. Verify a direct detail link, refresh, assets, report creation, reset, and a fresh browser session. State that data is stored separately in each browser.
5. Write a portfolio README with screenshots, features, setup steps, learning outcomes, test evidence, and limitations. Link your finished demo and record what you built yourself.

## Done when

- [ ] The production build and tests pass before deployment.
- [ ] Direct links and refresh work on the hosted demo, including any repository subpath.
- [ ] The portfolio clearly says frontend demo, fictional data, and no real account protection.
