# Cybersecurity Web Learning — Incident Tracker

A beginner’s path from basic HTML and CSS to a React security incident tracker, with an optional JavaScript backend.

**This repository contains instructions only.** There is no starter application, solution code, configuration code, or runnable project. You will write your application in a separate implementation repository. Every document includes instructions, a ChatGPT coaching prompt, and resource links.

## What you will build

First, create a static dashboard and report form using HTML and CSS. Add JavaScript behavior, then rebuild the interface with React. The core project lets a visitor create fictional incident reports, search and filter them, open details, update demo statuses, and retain demo data in the same browser.

The optional extension adds a Node.js and Express API, SQLite, authenticated users, and server-enforced permissions. The frontend milestone is a learning demo, not a confidential incident-reporting service.

## Instructions

1. Read the [project brief](PROJECT-BRIEF.md) to understand the features and field rules.
2. Follow the [roadmap](ROADMAP.md) in order. Start at [lesson 00](lessons/00-setup-and-git.md), even if React is your main goal.
3. Create a separate implementation repository for your own work. Keep this repository available as the lesson guide.
4. Read a lesson, study its resources, attempt one small task, and only then ask ChatGPT for a hint or review.
5. Use each lesson’s completion checks and record evidence in your [progress journal](PROGRESS.md).
6. Complete the frontend milestone before attempting the backend extension. Use the [coaching guide](COACHING.md) when you get stuck.

## Learning path

| Phase | Lessons | Result |
| --- | --- | --- |
| Foundations | 00–04 | Accessible HTML pages styled with plain CSS |
| Programming | 05–08 | JavaScript data operations, events, and HTTP understanding |
| React | 09–14 | Components, state, forms, routing, and demo persistence |
| Quality and portfolio | 15–17 | Security review, tests, accessibility checks, and a hosted demo |
| Optional backend | 18–21 | API, database, sessions, permissions, and full-stack integration |

Use JavaScript first. Add TypeScript, a component library, or more advanced state tools only after you can explain the core application. A planning estimate is 8–12 weeks for the core at roughly 4–6 focused hours per week; take longer where needed. The backend is a separate advanced extension.
